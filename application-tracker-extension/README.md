# 求职投递记录与申请助手

Application Tracker 是一个 Chrome 扩展，用于管理投递记录、保存中英文申请资料，并在当前申请页面预览、核对和填写表单。需要 Chrome 120 或更新版本。

AI 默认关闭。本地资料匹配、复制、记录管理和备份无需 API；开启 AI 后，准备或更新问题时会按需请求 OpenAI，辅助理解题意和生成答案草稿。

0.4.0 增加可选的截图辅助识别。在「AI 设置」启用 AI 和「截图辅助识别」，保存支持图片输入的模型后，仍按「识别并预览 → 确认并填写」使用，无需额外逐题操作。

## 安装与更新

1. 打开 Chrome 的 `chrome://extensions/`，开启「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择当前 `application-tracker-extension` 文件夹。
3. 在扩展列表中找到 **Application Tracker**，按需固定到工具栏。

更新源文件后，在 `chrome://extensions/` 点击该扩展的刷新图标，再关闭并重新打开弹窗、侧栏及记录页。回到申请网站后重新识别页面，不继续执行更新前的填写计划。不要把仓库中的历史 `dist/` 目录当作当前源码加载。

## 记录和管理投递

在招聘页面点击扩展图标，弹窗会预填当前链接、网页标题、当天日期和可识别的投递来源。CTgoodjobs、JobsDB 和支持的 Moka 页面还会尝试提取公司、岗位和地点；提取结果请自行核对。

补全公司、岗位、Base、进度、跟进日期、JD 和备注后点击「保存记录」。链接或公司与岗位重复时，会提示是否仍要保存。未保存的弹窗草稿会按岗位链接暂存；回到同一页面可继续，点击「清空草稿」可重新开始。草稿只在当前浏览器会话内暂存，请及时保存正式记录。

「查看全部」打开表格页，支持公司或岗位搜索、状态筛选、日期排序、逐条编辑、批量改状态和删除。独立看板按已投递、笔试、面试、Offer、Rejected、冻结分组；一面、二面和终面归入面试，撤回归入 Rejected。表格和看板会同步数据变化，状态修改会追加进度时间线。

日期按本机日期计算。跟进日期临近或逾期时高亮；当前仍共用「下次跟进 / 截止日期」字段，不提供独立的面试日历或定时提醒。

## 使用申请助手

1. 在「申请信息」中打开「编辑个人信息」，保存中英文资料；无需另行生成 AI 信息库。
2. 回到申请网站，点击扩展的「申请信息 → 打开申请助手」。顶部显示助手绑定的页面；切换标签页不会自动改绑，需点击「改为当前页面」。
3. 选择申请语言，点击「识别并预览」。助手读取题目与真实选项，准备本地或 AI 建议；此时不向网页写入答案。
4. 有效答案默认选中，包括可校验的 AI 草稿和已确认记忆，无需逐题勾选。重点查看标记项，或切换「只看需处理」。补充、修改后的有效答案自动加入本次填写；也可取消不需要的项目或使用全选。
5. 点击一次「确认并填写 N 项」。助手逐项写入并回读核验，结果区列出已核验和未完成项目。
6. 在网站核对最终内容，再自行保存或提交申请。

长文、签证或工作资格、薪资等已有有效答案的项目会在预览中突出标记，查看后随整批一起确认。缺少资料、格式不合要求或未能读取真实选项的控件不会进入填写批次。验证码、密码、文件上传、同意声明、签名及最终提交由用户在网站处理。

助手会尝试展开受支持的下拉框，读取当前可见的真实选项，必要时用明确的学校、专业或公司资料搜索。不会把 AI 生成的选项当成网站已有选项。读取失败、选项变化或无法唯一匹配时，应回到网站手动处理。

截图辅助在文字题意不明确时读取当前可见区域，例如图片里的题目、分区或本科/硕士标题。识别结果只对应到已经找到的表单控件，再从已有资料匹配答案；预览中标注「截图辅助」并提示重点核对。保持申请页为当前标签，并从该页面点击扩展图标授予截图权限。视口外的疑难题可滚动到可见区域后更新预览；不自动翻页或滚动整页。无截图权限、模型不支持图片或页面发生变化时，保留文字识别结果并显示原因。

「停止」会停止后续处理；已完成的填写保留。页面允许时，「撤销本次填写」可恢复助手写入前的值；用户后来修改过的内容不会强行覆盖。网站自身的保存、提交及服务器状态不属于撤销范围。

页面新增问题、条件选项变化或经历块变化后，点击「更新预览，保留修改」。结构和资料一致时保留修改与明确取消的选项；新的有效答案加入预览，需再次统一确认才填写。填写中发现变化会自动更新预览并停下等待确认。资料或记忆变化后，旧计划也需要更新。

## 个人资料与问答记忆

个人资料是事实来源；问答记忆是经过确认、限定范围的可复用答案，两者分开保存。填写成功不会自动把答案加入长期记忆。

结果区可「批量保存本次答案」，也可保存单项或「学习网页已填写的答案」。学习预览默认选中可用答案，核对后一次确认保存；同一字段多次填写只批量保存最近一次成功答案。默认限定为当前岗位链接；适合跨岗位复用时可选择「通用答案」。岗位编号和路由保留在适用范围中，常见登录凭据与跟踪参数会移除。旧版缺少可靠范围的记忆保留待确认。

「记忆库」可查看、编辑、删除和重新确认答案。详细资料说明见 [个人信息与申请信息](docs/autofill-profile.md)。

## 完整备份与恢复

在「记忆库」或个人信息页的「备份与恢复资料」打开备份入口。

- **导出完整备份**：下载 JSON，包含投递记录、个人资料、当前问答及历史问答备份；不含 API Key、AI 设置、临时草稿和侧栏会话。
- **导入 JSON 备份**：先校验文件和显示数量预览，再选择合并或替换，最后点击「确认恢复」。
- **合并**：相同 ID 保留本机内容；本机已有个人资料时整份保留。若备份资料不同，新加入的问答会设为待核对，避免经历对应错误。
- **替换**：以备份内容替换记录、资料和问答。兼容旧版仅含资料与问答的 JSON；导入这种旧备份时保留现有投递记录。
- **导入前恢复点**：每次恢复前在本机保留一份完整恢复点，可再次预览并恢复。它会随后续导入更新，不能替代下载到电脑上的备份。

预览之后如果其他页面修改了数据，恢复会要求重新预览。格式错误或不支持的备份不会直接覆盖数据。JSON 文件上限为 20 MB，实际可恢复容量还受 Chrome 本地存储配额约束。

换电脑或重装浏览器前，下载完整 JSON 备份；新环境加载扩展后导入，并重新配置需要的 AI 设置。

### Excel 只备份投递记录

表格页「导出 Excel」生成 `.xlsx`：第一张「投递记录」使用中文表头，隐藏的 `_restore_data` 表用于恢复。

「导入 Excel」会覆盖当前投递记录；有现有记录时，会先下载一份 `application-records-backup-before-import-日期.xlsx`。Excel 不包含个人资料、问答记忆或 API Key，请勿将它当作整套插件数据备份。

## 数据与权限

持久数据保存在当前 Chrome 配置的 `chrome.storage.local`，临时草稿和助手会话保存在 `chrome.storage.session`。当前没有云端同步。

声明的浏览器权限为 `storage`、`activeTab`、`scripting`、`tabs`、`sidePanel` 和 `webNavigation`；固定网站权限包括 CTgoodjobs、JobsDB、Moka、`job.swsmu.com` 和 `api.openai.com`。其他申请页面通过用户打开扩展所授予的当前标签页权限处理。跨域内嵌页面可能无法访问，助手会显示检查覆盖范围。没有 `<all_urls>` 权限不代表助手只会读取这几个招聘网站。

开启 AI 后：

- 题意理解会发送待识别或需要复核的问题、分区、提示、约束、选项及资料类别，不需要发送个人资料值。
- 答案建议按题目发送相关个人资料片段、页面标题和提取到的岗位背景，可能包含姓名、联系方式、教育和经历等与题目有关的内容。
- 文字请求不附带网页已有答案，完整网址和 API Key 不放入提示词；API Key 作为请求鉴权信息发送到 OpenAI。
- 截图辅助单独默认关闭，启用后按需发送当前申请页可见区域的遮盖截图及字段编号。输入控件、已有内容区域和内嵌页面会先遮盖；其他可见文字或图片仍可能含个人信息，不能视为完全匿名。原图和处理后的截图只在本次处理内存中使用，不保存到本地记录、会话或备份。
- 请求使用 `store: false`，但扩展本身不对服务商的数据处理政策作额外保证。侧栏可查看本次 AI 发送范围。

关闭 AI 不产生 AI 请求；已有本地资料仍可使用。常规投递记录导入、导出及备份在本地完成。

## 验证与限制

已使用隔离的 Chrome 环境和虚构表单检查页面识别、真实选项、填写回读、撤销、跨页面数据更新及备份恢复等流程；没有读取真实用户资料。测试包含纯逻辑检查、浏览器表单测试、带 Chrome API 适配器的界面测试，以及加载真实 MV3 扩展的隔离环境测试。

**尚未完成真实招聘网站或真实 AI 服务的现场验证。** 虚构页面通过不代表任意 Moka、Phoenix 或其他网站均可正确填写。关闭的 Shadow DOM、不可访问的跨域区域和未适配控件需要手动处理。

截图辅助仅识别当前视口主页面内可关联的表单控件；内嵌页面在截图中遮盖，仍依靠原有文字扫描。纯图片或画布中没有可识别表单控件的内容不能自动填写，也不支持让模型任意点击坐标。未用真实 AI 检验识图准确率。

在源码目录执行：

```powershell
npm.cmd test
npm.cmd run test:browser
npm.cmd run test:ui
npm.cmd run test:data-ui
npm.cmd run test:extension
npm.cmd run test:vision-browser
```

浏览器测试需要可用的 Playwright 与 Chrome；可通过 `BROWSER_EXECUTABLE` 指定测试浏览器。当前截图辅助的验证范围见 [0.4.0 验证记录](../docs/2026-09-26-visual-recognition.md)。历史结果见 [0.3.1 预览流程验证](../docs/2026-09-22-preview-confirmation.md) 和 [0.3.0 验证记录](../docs/2026-09-22-reliability-verification.md)。发布前另见 [发布检查清单](RELEASE_CHECKLIST.md) 和 [更新记录](CHANGELOG.md)。
