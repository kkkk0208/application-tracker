# 0.3.0 可靠性修正与验证

日期：2026-09-22。源码目录：`application-tracker-extension/`。`manifest.json` 与 `package.json` 均为 **0.3.0**。

## 问题与修正

这轮不稳定的直接原因主要在题目理解、控件操作和状态同步链路：宽泛关键词会把学校所在地、专业排名或学位成绩识别为另一种资料；准备答案时缺少真实下拉选项；网页重绘、慢加载和手动改动后，原计划与控件状态容易脱节。仅升级模型不能修正这些执行问题。

- **识别与建议**：收紧明确字段的本地规则；结合分区、帮助文字、约束、主体和冲突线索复核疑难题；不把学校名称用于学校所在地等问题。AI 只能引用可用事实或网页已有选项，草稿需要核对。
- **真实选项与填写**：先展开并读取受支持的下拉框；搜索只使用明确资料，读取后恢复菜单状态。等待真实加载与写入反馈，唯一对应的重建控件可重新定位；选项改变、用户输入或无法确认的变化会停止旧操作。
- **动态页面**：新增问题或级联选项变化后更新预览；保留仍对应同一问题的草稿，新问题重新勾选。切换语言不继承原语言草稿；过期的后台检测结果不会覆盖新会话。
- **取消与结果**：异步等待锁或保存操作状态后再次检查取消；填写回读、撤销和操作标识防止重复写入。保存结果按具体操作定位，保留该次答案的主体、语言及岗位；保存整批记忆时冻结内容并锁定预览，防止错配。
- **数据一致性**：持久数据修改经后台串行队列处理；表格和看板同步，只提交实际修改的字段，对同字段的并发编辑提示冲突。使用规范化对象版本避免 Chrome 序列化顺序导致误报资料变化。
- **资料与恢复**：记忆范围保留岗位标识，旧范围待重新确认；资料直接用于建议。增加完整 JSON 备份、预览、合并/替换与导入前恢复点，排除 API Key；弹窗草稿按岗位暂存，日期按本机当天计算。

## 最终验证

环境：Windows、本机 Chrome **153.0.8010.50**、隔离临时浏览器与虚构资料。所有以下运行均成功退出，共 **223 项**。

| 验证入口 | 结果 | 验证重点 |

| `npm.cmd run test:browser` | 32 / 32 | 真实网页控件、异步选项、用户改动、重绘、回滚、撤销、跨框架及岗位上下文边界 |

| `npm.cmd run test:data-ui` | 8 / 8 | 表格/看板同步、编辑冲突、记忆范围、备份预览/合并/恢复及窄屏 |

助手界面和数据界面测试使用明确的 Chrome API 适配器；其中 AI 响应是本地模拟。真实扩展测试使用真实工作线程和 Chrome 存储，与适配器测试分开计数。备份往返验证实际存储内容一致、预览不写入、导入和恢复不覆盖 API Key。

## 验证边界与使用

没有调用真实 AI 服务，也没有在用户登录的真实招聘网站填写或提交申请。上述结果不代表所有招聘系统、自定义控件或不可访问的跨域区域均兼容，也不是与 Claude 浏览器控制能力的实测对比。

更新后打开 Chrome 的 `chrome://extensions/`，刷新 **Application Tracker**，重新打开插件弹窗、侧栏与管理页，在申请网页重新识别。本轮更新的是源码，历史 `dist/` 包没有被覆盖。

修改前源码备份保留在 [source.zip](backups/before-reliability-fixes-2026-09-21/source.zip)。这是源码恢复备份，不是用户浏览器中的个人资料备份；个人数据应使用插件内的“导出完整备份”。

使用步骤见 [README](../application-tracker-extension/README.md)，变更见 [CHANGELOG](../application-tracker-extension/CHANGELOG.md)。
