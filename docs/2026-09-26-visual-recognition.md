# 0.4.0 截图辅助识别与验证

完成日期：2026-09-26。源码：`application-tracker-extension/`，版本 0.4.0。

用户希望补上截图视觉识别，并保留“识别后先显示预览，再一键确认填写”。本次实现的是对已有表单控件的截图辅助理解，日常流程仍为「识别并预览 → 确认并填写」。

## 使用

1. 在 `chrome://extensions/` 刷新 Application Tracker，关闭并重开扩展页面。
2. 在「AI 设置」启用 AI 和「截图辅助识别」，填写 API Key 及支持图片输入的模型并保存。现有模型设置不会被替换，截图开关默认关闭。
3. 回到申请页面，从该页面点击扩展图标打开助手，并保持该页为当前活动标签。
4. 点击「识别并预览」。有需要时自动发送遮盖截图；预览标注截图辅助的问题，查看后一次确认填写。

没有截图权限时会提示重新点击扩展图标；图片模型不可用、请求失败或页面变化时保留普通文字预览。

## 实现范围

- 先扫描 DOM、读取真实选项并做本地资料匹配。只对题意、主体或教育层级不明确的空白可用字段补充视觉识别。
- 截图仅覆盖当前可见主页面，最多关联 30 个字段。字段使用 V1–V30 编号，模型返回题目、教育分区及置信度，不返回执行坐标或申请人事实。
- 仅接纳编号与字段唯一对应、置信度不低于 0.9、无语义冲突的结果。明确的 DOM 题意、学历、家属主体及受保护问题不会被视觉结果改写。
- 模糊标签可补充为图片中实际可读的问题；仍从个人资料及原有建议校验流程准备答案。视觉证据显示在预览，需核对项突出标出。
- 同题更新预览保留人工修改和手动经历绑定；原始问题、分组、选项、约束、文档或上下文变化时不盲目复用。
- 部分视觉响应只确认院校学历时，同组没有明确层级的专业等字段留待指定，不继续默认用硕士资料拼成混合答案。
- 不自动提交、翻页、添加经历块或任意点击坐标。纯画布表单没有可对应的 DOM 控件时不能自动填写。博士教育尚无对应资料模型，不接受视觉博士映射。

## 截图与数据

捕获前后检查目标活动标签、浏览器文档、页面滚动及布局。捕获期间切走再切回、短暂滚动后恢复、题目属性变化等仍使截图失效。取消或 AI 设置变化会停止后续处理。

在内存中的画布先遮盖输入控件、已有值的控件容器、内嵌页面及已识别答案区域，再缩小至最长边不超过 1600 像素并添加字段编号。原图、遮盖图不写入本地存储、侧栏会话或备份。没有新增 `<all_urls>` 或 debugger 权限。

遮盖不是完全匿名化：页面其他可见文字、图片、只读资料或未识别组件仍可能含个人信息。AI 设置明确提示这部分发送范围，截图需单独启用。

图像请求采用 Responses API 的 `input_image`、`detail: high`、严格 JSON 输出及 `store: false`，按用户已保存的模型调用。接口依据为 [OpenAI 图片输入文档](https://developers.openai.com/api/docs/guides/images-vision)。截图调用采用现有 activeTab 权限，依据 [Chrome captureVisibleTab 文档](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab)。扩展不对服务商的数据处理政策作额外保证。

环境为隔离 Chrome 153.0.8010.54、Node 24.16.0，使用虚构资料；未读取用户浏览器资料、问答或 API Key。测试截图只含虚构界面，已查看 320 像素宽侧栏预览。

界面测试通过 Chrome API 适配器和本地 AI 响应模拟，验证图片题目对应真实输入框、正确使用本科资料、确认前无写入、一次确认后核验、刷新保留手改答案及绑定、部分视觉响应不混用本科硕士、关闭截图无请求、错误活动标签拒绝捕获及图片 API 错误回退。模拟截图使用浏览器截图接口，不用会临时修改页面样式的截图方式干扰布局观察。

截图测试在真实 Chrome 中逐像素确认输入框、密码、已填内容容器、iframe、开放 Shadow DOM 控件和答案块遮盖，验证缩放后仍遮盖，以及标签属性、滚动和布局瞬变被拒绝。

真实扩展测试验证原有填写、数据与备份链路，以及实际截图权限不足时的提示和设置页开关保存。**未模拟授予 activeTab 来宣称真实扩展截图成功；实际截图成功到模型的整条路径仍需在用户点击扩展后的环境现场验收。**
